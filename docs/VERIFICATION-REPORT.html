五、已知注意事项与踩坑记录(复现前必读)

5.1 平台限制(不可解决)

限制影响说明与替代方案
DevEco Code 无 Linux 版AI 编程华为只发布了 macOS(ARM64/x64)平台包,Linux 二进制未上线(npm 404)。替代:容器内已装 Claude Code(通用 AI 编程)+ devecocli(鸿蒙工程/构建/模拟器/文档),组合覆盖 DevEco Code 全部核心能力。等华为发布后一条命令补装:npm i -g @deveco/deveco-code
Gradle 未预装安卓构建按清单口径,工程自带 ./gradlew 优先;镜像内置 aapt2/zipalign/apksigner 最小构建链已验证通过
安卓模拟器无窗口远程观看无头模式运行,用 adb exec-out screencap 获取画面;如需 VNC 观看安卓,可切窗口模式(去掉 -no-window 参数)

5.2 已修复并内置到镜像的问题

问题症状修复方式
鸿蒙许可未接受模拟器启动报协议错误已写入 Dockerfile 构建层:Emulator -license accept
hdc 不在 PATHbash 报 command not found已建软链:ln -sf .../hdc /usr/local/bin/hdc

5.3 使用时需注意的操作细节

事项出错表现正确做法
鸿蒙装包版本"install failed due to older sdk version"工程 targetSdkVersion 须 ≤ "6.1.1(24)"(模拟器系统版本);CLT26 脚手架默认 API 26,构建前修改 build-profile.json5
鸿蒙截图路径"filename invalid"截屏必须保存在 /data/local/tmp/xxx 下,其他路径一律报错
装包时机"can not specify user in shell"鸿蒙模拟器开机后等约 45~60 秒系统服务就绪,再执行 bm install
端口hdc/adb 连不上每个鸿蒙实例占 2 个端口(5555 递增);安卓用 5554/5556;多实例时注意端口冲突
VNC 端口映射本地 VNC 连不上Docker 启动时必须加 -p 5900:5900;容器内先起 Xvfb(虚拟屏)再起 x11vnc
容器间状态不共享--rm 后再进找不到之前的文件每次 --rm 是全新容器;需持久化的文件挂载 -v 到宿主机;或多实例用 docker run -d --name 保持运行

5.4 测试脚本 bug 记录(非镜像缺陷)

Bug原因修复
keytool 命令找不到测试脚本未加 $JAVA_HOME/bin 到 PATH脚本头补 export PATH=$JAVA_HOME/bin:$PATH
hdc list targets 空新容器内 hdc 服务未启动先执行 hdc start 再查设备
adb 多设备报错双端同时在线时 adb 不知道操作哪台加 -s 设备ID 参数指定目标
安卓 APK 安装失败测试用最小包无 classes.dex,Android 14 拒绝无代码应用测试用例限制;真实 ./gradlew 产物含完整字节码无此问题

6.3 五个常用场景(复制即用)

场景 1:纯开发/编辑代码(不需要虚拟化)

docker run -it --rm \
  -v /你的工程路径:/work \
  harness-dev:2.1

# 进入后你可以:
#   git clone / git commit ...
#   python3 脚本.py
#   rg "关键词" --type ts
#   jq '.key' 文件.json
#   gcc main.c -o app

不需要 --device /dev/kvm,任何 Docker 环境都能跑。

场景 2:构建鸿蒙应用(HAP)

docker run -it --rm -v /你的鸿蒙工程:/work harness-dev:2.1

# 容器内执行:
cd /work/你的项目
hvigorw assembleHap --mode module -p module=entry@default

# 产物位置:entry/build/default/outputs/default/xxx.hap
⚠️ 注意:工程 build-profile.json5 的 targetSdkVersion 须 ≤ "6.1.1(24)"(模拟器系统版本),CLT26 脚手架默认 26,需手动修改。

场景 3:启动安卓模拟器(需要 KVM)

# 一键启动(自动创建 AVD → 开机 → 等待就绪)
docker run --rm --device /dev/kvm harness-dev:2.1 /opt/scripts/start-android.sh

# 或交互模式,自己控制
docker run -it --rm --device /dev/kvm \
  -v /你的工程:/work \
  harness-dev:2.1

# 容器内:
/opt/scripts/start-android.sh my_avd     # 启动
adb devices                              # 查看设备
adb install /work/你的.apk               # 安装应用
adb shell input tap 360 800              # 点击屏幕
adb exec-out screencap -p > 截图.png     # 截图

开机约 1~2 分钟;Android 14 / API 34 / Pixel 6 仿真机,无头模式运行。

场景 4:启动鸿蒙模拟器(需要 KVM)

docker run -it --rm --device /dev/kvm \
  -v /你的工程:/work \
  harness-dev:2.1

# 容器内:
/opt/scripts/start-harmony.sh my_hm     # 启动(约1-2分钟)
sleep 45                                  # 等系统稳定

# 连接与操作:
hdc tconn 127.0.0.1:5555                 # 连接
hdc -t 127.0.0.1:5555 shell "echo ok"    # shell
hdc -t 127.0.0.1:5555 file send /work/app.hap /data/local/tmp/a.hap  # 送包
hdc -t 127.0.0.1:5555 shell "bm install -p /data/local/tmp/a.hap"    # 安装
hdc -t 127.0.0.1:5555 shell "aa start -a EntryAbility -b 你的包名"   # 启动
hdc -t 127.0.0.1:5555 shell "snapshot_display -f /data/local/tmp/s.jpeg"  # 截图
hdc -t 127.0.0.1:5555 file recv /data/local/tmp/s.jpeg /work/截图.jpeg    # 取回
⚠️ 截图路径必须在 /data/local/tmp/ 下,其他路径报错。

场景 5:Claude Code 执行 AI 任务

# 无头模式(全自动,输出 JSON)
docker run --rm \
  -e ANTHROPIC_API_KEY=你的密钥 \
  -v /你的工程:/work \
  harness-dev:2.1 \
  claude -p "把 /work/src 里的 Java 文件迁移到 ArkTS" --output-format json

# 交互模式(人机对话)
docker run -it --rm \
  -e ANTHROPIC_API_KEY=你的密钥 \
  -v /你的工程:/work \
  harness-dev:2.1 \
  claude

需要 Anthropic API 密钥;不设密钥可先跑 claude --help 验证安装。

6.4 双端同时运行(鸿蒙 + 安卓并排)

docker run -it --rm --device /dev/kvm \
  --name dev \
  -v /你的工程:/work \
  harness-dev:2.1

# 容器内先起安卓再起鸿蒙:
/opt/scripts/start-android.sh avd1
/opt/scripts/start-harmony.sh hm1
sleep 30

# 现在双端同时在线:
adb devices                    # 安卓
hdc list targets               # 鸿蒙
# 可以同时操作双端做迁移对照测试

场景 6:VNC 远程桌面看模拟器画面(需要 KVM + 端口映射)

# 注意:比普通场景多一个 -p 5900:5900(端口映射)
docker run -it --rm --device /dev/kvm -p 5900:5900 \
  -v /你的工程:/work \
  harness-dev:2.1

# 容器内:
/opt/scripts/start-harmony.sh my_hm    # 先起模拟器(创建虚拟屏)
x11vnc -display :0 -forever -shared -rfbport 5900 -passwd 你的密码 &
# 看到端口监听后,在本地连接:
本地系统连接方式
macOS访达 → ⌘K → 输入 vnc://localhost:5900 → 密码
Linuxremmina 或 vncviewer localhost::5900
WindowsVNC Viewer → localhost:5900

连接后可实时看到鸿蒙模拟器的手机画面(通过虚拟屏 Xvfb),可以用鼠标直接操作。

6.5 常见问题排查(FAQ)

问题原因与解决
/dev/kvm 不存在宿主机未开虚拟化。云主机需开通嵌套虚拟化;裸金属检查 BIOS VT-x 设置。
安卓模拟器黑屏正常,无头模式无 UI。用 adb exec-out screencap 获取屏幕内容。
鸿蒙装包报"版本不兼容"工程 targetSdkVersion 超过模拟器系统版本。修改 build-profile.json5 为 "6.1.1(24)"。
鸿蒙截图报路径无效截屏路径必须 /data/local/tmp/xxx,不能在其他目录。
鸿蒙装包一直失败模拟器开机后需等约 45~60 秒系统服务就绪,再 bm install。
hdc 命令找不到镜像已内置 PATH;若手动环境需 export LD_LIBRARY_PATH=/opt/command-line-tools/sdk/default/openharmony/toolchains
Gradle 构建报错镜像未预装 Gradle(按清单口径,工程自带 ./gradlew 优先)。若需全局装:npm i -g gradle 或下载 Gradle 8.14。
内存不足(OOM)双端模拟器约需 13G;确保容器可用内存 ≥ 16G。
